## 1. Название проекта

«НаХодНоги» — онлайн-каталог обуви с возможностью заказа.

## 2. Проблема

Учёт ассортимента, заказов и клиентов ведётся в Excel-таблицах: покупатель не может посмотреть каталог и оформить заказ онлайн, менеджер тратит время на ручное обновление остатков и ведёт записи в нескольких файлах, данные расходятся между листами и теряются.

## 3. Пользователи

- **Гость** — просматривает каталог обуви, фильтрует по размеру и категории, оформляет заказ без регистрации;
- **Менеджер** — ведёт каталог (добавляет, редактирует, удаляет товары), управляет заказами и остатками, видит список заказов;
- **Администратор** — управляет пользователями и правами доступа, может назначать менеджеров и просматривать всю статистику системы.

## 4. Цель проекта

Дать гостю возможность выбрать обувь и оформить заказ онлайн, а менеджеру — управлять каталогом и заказами в единой системе вместо разрозненных Excel-таблиц.

## 5. Метрики успеха

- время оформления заказа гостем — < 3 минут;
- гость находит нужную пару через фильтры — за < 3 кликов;
- остатки обновляются сразу после оформления заказа, без ручного ввода в Excel;
- менеджер добавляет новый товар в каталог — за < 1 минуты.

## 6. Границы (что НЕ делаем)

- не подключаем реальные платёжные шлюзы (оплата — учебный симулятор, статус «оплачено» ставит менеджер);
- нет мобильного приложения — только веб-интерфейс (desktop-first);
- доставка не моделируется — заказ выдаётся в магазине;
- нет системы отзывов и рейтингов товаров;
- нет интеграции с 1С или внешними складскими системами.

## 7. Риски

- **Не успеем реализовать все роли к дедлайну** → приоритизация: сначала каталог и заказ для гостя, затем панель менеджера, администратор — в последнюю очередь;
- **Сложно спроектировать БД под три роли** → начинааем с минимальной схемы (товары, заказы, пользователи), расширяем по мере необходимости;
- **Данные из Excel перенести некорректно** → сначала проверяем структуру исходных таблиц, при расхождениях нормализуем вручную, а не импортируем «как есть».
